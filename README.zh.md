# Trunook

[Русский](README.md) · [English](README.en.md) · **简体中文**

把 MacBook 的刘海变成工作台：音乐、会议、剪贴板、文件、笔记，以及你自己的
语言模型——都在目光已经落着的地方，而不是压在工作之上的十来个窗口里。

![工作中的刘海](docs/demo.gif)

**一切都在你自己的电脑上运行。** 模型、语音识别、笔记和剪贴板历史都不会外
传。确实会外传的内容及其去向，[单独列了一节](#有什么会离开你的电脑)，每一个
请求都写清楚。

## 刘海是怎么用的

一共四种状态，靠手上的动作切换，不用去瞄准按钮。

| 你的动作 | 会发生什么 |
|---|---|
| 悬停 | 迷你视图：正在播放什么、下一场会议在什么时候 |
| 点按或向下轻扫 | 展开整个主屏幕 |
| 向上轻扫 | 收回去 |
| 按住不放 | 圆钮环：所有功能像扇子一样展开——把手移过去松开即可 |
| 右键点按 | 同样的圆钮环，但会留在原处：点选一个，点别处关闭 |

![手势](docs/gestures.png)

收起的刘海也会说话：计时器走着时显示读秒，咖啡杯亮着时显示剩余时间，会议
之前显示倒计时。点一下这条就能直接进入对应面板。

**键盘与朗读。** 每个面板都有自己的快捷键，设置可以用 Tab 键走遍，图标说明
由 VoiceOver 读出。系统的“减弱动态效果”和“降低透明度”都会被遵守。

**省电。** 空闲时刘海几乎不占用处理器，显示器休眠时则完全不占用。节能模式下
（随 macOS 低电量模式开启，或使用电池时也开启，在“通用”中选择）动画静止，
剪贴板、音乐和会议的检查频率降低，摘要和笔记关联会等到接通电源。

## 主屏幕

展开的刘海像手机主屏幕一样由磁贴组成。磁贴显示要点、完成要点操作：暂停、
启动计时器、加入会议。点按磁贴则打开完整面板。

应用会做的事几乎都有对应的磁贴——从音乐、会议、日程时间轴，到饮水、系统
负载、笔记和文件架，另外还有语音、听写和提词器的快捷入口。尺寸从 1×1 到
4×2，排在四列网格中。在设置的 **“主屏幕”** 里挑选磁贴、顺序和大小，用鼠标
拖动即可。

命令磁贴略有不同：上面最多可以放四条自己的命令，1×1 尺寸放一条。在别的
窗口里选中文字，点一下磁贴上的“翻译”，模型的回答就会直接在刘海里打开。

## 功能

### 日程与时间

- **日历。** 带周数的月历和所选日期的安排就在刘海里；点击事件即可就地编辑
  ——时间、地点、描述、参与者与链接。当天的安排可以用列表或时间轴呈现，
  翼上的按钮可以互相切换：在时间轴上，色块高度就是时长，空档一目了然，
  同时进行的会议并排成列，还有一条“此刻”横线。会议开始前刘海会提前提醒并
  倒数分钟。今天的任务会从 Things 3 中读取。
- **线上会议。** 通话进行时，悬停即可使用麦克风、摄像头、屏幕共享、举手和
  退出——浏览器中的 Telemost、Google Meet、Zoom 和 Teams，以及 Telemost 和
  Zoom 的桌面应用（Zoom 提供麦克风、摄像头和共享）。录制按钮也在那里：它会
  同时录下你和对方，语音在本机转成文字并生成笔记——标题、摘要和单独列出的
  待办，并附上录音。录制需要 macOS 26，默认关闭。
- **可以直接回答的通知。** 刘海下的提示条不再只是告知，还会提问：到点的提醒可以
  标记完成或推迟十五分钟，结束的计时器可以延长或重新开始，模型准备写入的内容
  也能直接确认或取消，无需展开面板。来电同样出现在这里——接听和拒接都可以在
  刘海里完成（Telephone、Zoiper、Linphone、Bria、3CX、Telegram）。任何脚本也能
  借助刘海来问你：把问题写成文件放进应用的文件夹，然后等你按下哪个按钮。来电和
  脚本提问默认关闭。
- **计时器与秒表。** 时间用带刻度的转盘选择，还有二十五分钟的番茄钟并自动
  接上休息。计时进行时刘海会展开成一条读秒；读数从启动那一刻算起，即使
  合上过盖子也不会落后。
- **倒计时。** 显示你自己的事件以及距离它还剩多久的磁贴。时间到时会弹出
  提示，并从刘海喷出彩带。

### 文字、文件与笔记

- **剪贴板历史。** 复制过的内容随手可取：可用键盘按编号粘贴，列表打开时
  ↑↓ 移动选中行，回车粘贴。
- **文件架。** 把文件拖到刘海上就放进了文件架；再拖进任意窗口，文件就搬了
  过去。在刘海上方还能直接扔进某个区域：压缩成 ZIP 或解压、把 iCloud 链接
  放进剪贴板、丢进废纸篓。
- **笔记。** 带格式和清单的多行输入，标题由模型拟定。列表支持按词搜索、
  导出为 Markdown，最多可置顶三条。别人的文字不用重打：任意窗口中选中的
  文字和复制过的内容，各有自己的快捷键直接存进笔记。开启 Obsidian 同步后，
  笔记会存放在库中的子文件夹里、两边都能编辑，模型还会把语义关联以真正的
  `[[链接]]` 写入文件。
- **提词器。** 文字就在刘海正下方——摄像头所在的位置——支持格式和自动滚动：
  从屏幕中部读稿，视线正好掠过镜头。

### 本机上的模型

- **在刘海里提问、看答案。** 回车发送问题，答案直接写在刘海下方，可以复制
  或粘贴到当前窗口；正在生成时，发送按钮会变成停止。Ollama 会自行安装：应用会下载并启动它，并按机器性能
  推荐模型——对话用的轻量、中等和强力三档，外加一个用于笔记的模型。合适的
  那个会标注“推荐”，一个按钮即可装好这一对。
- **自建服务器或云端。** 另一个具备 OpenAI 接口的本地服务器（LM Studio、
  llama.cpp、vLLM、Unsloth Studio），或者云端服务——OpenAI、Anthropic、
  Gemini、OpenRouter、Groq、DeepSeek。这些地址会自动填好，其余可用自定义
  供应商接入。可以同时保留多个，各有各的地址、密钥和模型。
- **会动手的助手。** 如果你允许，模型不只回答，还会动手：设置计时器、查看
  日程和天气、创建事件、提醒事项或笔记。读取类操作立即执行，写入类只有在
  刘海中确认“创建 / 取消”之后才会执行。在问题里输入 @ 号会列出会议和笔记，
  选中的内容会以词语形式进入问题——“@例会 改到周二 15:00”。在问题开头加一个
  斜杠就能直接指定工具：“/设置 怎么打开喝水提醒”会去查应用的使用说明，而不是
  让模型自己判断该找哪里。它也会回答关于
  应用本身的问题——“这里都有哪些功能？”“新闻摘要怎么设置？”——并说出该在
  设置的哪一节里打开。默认关闭；需要会调用工具的模型。
- **语音与听写。** 你可以直接开口提问：面板不会展开——刘海会轻颤并发光，
  聆听时是蓝色，思考时是模型的颜色——旁边还有音量条。模型一边写答案一边
  朗读；读完之后刘海会继续听，追问不必再做一次手势。提问栏里的麦克风会在
  你说话时把语音直接放进输入框，整条笔记也是这样口述的。语音在本机识别。
- **命令。** 它会抓取其他窗口中选中的文字并打开对话：抓取到的内容显示在
  输入框上方，命令列表在下方。命令数量不限，每条向模型的请求都有自己的
  模型——显示在行右侧，用 Tab 键切换。命令不只是向模型提问：还可以是应用、
  文件夹、链接、AppleScript、“快捷指令”里的命令，或把抓取内容存进笔记。
  前九条可以直接用键盘运行，常用的还可以作为磁贴放到主屏幕上。

### 周围发生了什么

- **音乐。** 曲目、封面、播放控制，以及沿岛屿轮廓的播放进度线。适用于任何
  播放器——数据来自系统。两指轻扫即可切换曲目。
- **天气与电源。** 面板角落或磁贴上显示带温度的图标，天气变化和插上电源时
  会弹出提示。
- **系统负载。** 处理器、内存和磁盘以进度条显示；点击即可打开“活动监视器”。
- **新闻摘要。** 设定主题和时间表，模型会为每个主题收集至多五条要闻：标题、
  来源、时间，以及一句话说明为什么重要。链接取自信息流而非模型，因此它编不
  出地址。摘要可以存进笔记或保存为文件，往期可以翻阅。主题也可以由模型自行
  建议。
- **网站跟踪。** 给出链接，再用文字说明要盯住什么：价格、库存、日期、剩余
  名额，任意一段文字。页面会按计划打开，数值一变，刘海就显示“原值 → 现值”，
  并带一个打开网站的按钮。数字还支持“低于”“高于”和阈值条件。

### 窗口与屏幕

- **窗口布局。** 拖动窗口标题栏到刘海，会显示布局：中间是全屏和居中 85%，
  两侧对称为半屏、三分之二、三分之一，以及上下四分之一。把窗口放到所需布局
  上即可。
- **多显示器。** “屏幕”设置：岛屿只出现在带刘海的屏幕上、出现在光标所在的
  屏幕上，或者同时出现在所有屏幕上。没有刘海的屏幕平时什么也不画，在“所有
  屏幕”模式下则是一条细带，悬停即可在那里展开岛屿。
- **玻璃质感。** 刘海下方的面板会透出壁纸，而刘海本身保持纯黑：岛屿不是浮在
  屏幕之上，而是从硬件里流出来的。透明度用滑块调节，推到最右侧刘海又变回
  纯黑。玻璃需要 macOS 26；更低版本下应用照常工作。

### 照顾自己

- **休息提醒。** 提醒休息、喝水和活动身体，各有各的间隔，且只计算使用电脑
  的时间。提示会等你回应：完成或跳过。饮水提醒上的对勾还会顺便问你喝了
  多少——50 到 1000 毫升的带刻度滑块，并标出这是多大的容器——此后便会显示
  当天总量；同样的数字也在“饮水”磁贴上。刻意不设目标：人不会整天守在电脑前。
- **咖啡杯。** 开启期间屏幕既不变暗也不锁定。时长在刘海里选择——半小时、
  一小时、一个半小时、两小时，或不限时；开启时剩余时间就显示在刘海上。
- **键盘清洁。** 把键盘锁住 30、60 或 90 秒——擦拭时不会输入任何字符。鼠标
  照常可用：刘海里有倒计时和“解锁”按钮。需要辅助功能权限。

### 让人会心一笑的小东西

- **刘海里的猫。** 当刘海没什么可显示时，一只像素“面包猫”会从下面跑出来：
  盯着光标、甩尾巴、睡觉、倒挂着沿边缘奔跑、玩毛线球、发脾气、抽烟、送飞吻、
  追自己的尾巴、扑光标，还会戴上墨镜。它还会抓老鼠、在遮阳伞下边喝
  冰沙边晒太阳（这时刘海会像太阳一样发出黄光），以及追小鸟。频率可设置：每 2–4、5–10 或 20–40
  分钟一次。全屏窗口、“减弱动态效果”和低电量模式下不出现。
- **刘海下的天气。** 天气变化时，刘海会下雨、飘雪、刮暴风雪、打闪电、升起
  太阳、飘出云朵，起风时云会疾驰而过。每次几秒钟，可以关闭。

| ⌃⌥S | 文件架 |

## 有什么会离开你的电脑

简单说：**默认只有检查更新**。其余都需要你自己打开，打开后外传的内容如下。

| 内容 | 去往哪里 | 默认 |
|---|---|---|
| 检查更新 | github.com | 开启，可关闭 |
| 天气 | open-meteo.com，坐标精确到约一公里——也可以只用城市名 | 关闭 |
| 向模型提问 | 设置中填写的地址：默认是本机上的 Ollama | 本机 |
| 笔记关联的向量 | 同一个模型；使用本机模型时什么都不会外传 | 关闭 |
| 新闻摘要 | 按你的主题生成的搜索请求——发往 news.google.com | 关闭 |
| 网站跟踪 | 你自己添加的页面 | 关闭 |

笔记、剪贴板历史和文件架都留在本机：笔记和历史在应用自己的文件里，文件架只是
指向你自己文件的链接。Obsidian 库由应用从磁盘读取，并写入其中的子文件夹——
不会有任何内容从那里外传。

笔记正文只有两种情况会发给模型：开启“在笔记中查找”时，以及允许助手查阅笔记
时。如果模型在本机，它根本不会离开这台电脑。

## 安装

### 从源码构建——最稳妥的方式

```bash
git clone https://github.com/TruDevLab/Trunook.git
cd Trunook
make cert      # 一次性：自签名证书
make install   # 构建、签名并放入 /Applications
```

需要 Command Line Tools（`xcode-select --install`）。不需要 Xcode。

### 使用现成的镜像

从[发布页](../../releases)下载 `.dmg`，把应用拖进“应用程序”，然后解除隔离：

```bash
sudo xattr -r -c /Applications/Trunook.app
```

### 之后会自动更新

应用每天向 GitHub 查询一次是否有新版本，并在后台下载。准备好后，刘海里会出现
带按钮的提示：点击即可安装更新并重启应用。下载到的内容会用你自己签名时所用的
同一份签名校验——因此已经授予的权限在更新后依然有效，也不必重新解除隔离。
检查更新可以关闭。

## 系统要求

- **带硬件刘海的 MacBook。** 岛屿就住在刘海里；通过“屏幕”设置也可以显示在外接
  显示器上，只是那里没有刘海。
- **macOS 14 或更高。** 玻璃质感需要 macOS 26，录制对话同样如此；更低版本下
  应用不带这两项照常工作。
- **构建** 需要 Command Line Tools。
- **模型** 需要 [Ollama](https://ollama.com)，应用会自行安装。你自己的
  OpenAI 接口服务器或云端密钥同样可用。

界面支持俄语、英语和简体中文——默认跟随系统。

## 限制

### 没有 Apple 的签名

本项目没有付费开发者账号。在别人的 Mac 上，Gatekeeper 不会放行
（`spctl -a` 返回 `rejected`），无法进行公证，App Store 也不在考虑之列。
上面的安装顺序正因如此：从源码构建更省事——自己签名的东西系统不会多问——
而镜像则需要手动解除隔离。

### 辅助进程活在 Apple 的命名空间里

macOS 通过私有的 `MRMediaRemoteGetNowPlayingInfo` 提供曲目信息，而从
macOS 15.4 起，普通进程只能拿到空值：访问权限留给了标识符以
`com.apple.controlcenter.` 开头的进程。因此这个 XPC 辅助进程被命名为
`com.apple.controlcenter.TrunookHelper`。

这一做法并不能访问他人的数据——它解除的只是读取自身播放器状态的限制。Apple
随时可能在某次更新中堵上这个口子：那时消失的只有曲目名称，而这套绕行方案本身
被隔离在一个独立服务里。
